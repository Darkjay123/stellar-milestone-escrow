02 · Security model

Every common escrow exploit is blocked and tested

Every guarantee below is enforced in the contract and covered by a test.

⌁

No front-run setup

Set up by a constructor at the moment it's deployed. There's no init() call an attacker could race to make themselves the recipient.

✎

The right signature, every time

Only the client releases, only the arbiter resolves, and only the two parties can dispute. Every money move calls require_auth().

⟲

No double payments

A strict state machine per milestone. State is written before the transfer, so a milestone can't be paid twice.

⚖

The arbiter can't steal

The arbiter can only split a disputed milestone between client and freelancer. There's no third destination.

⏱

Funds never get stuck

After the deadline, anyone can trigger a refund of pending milestones, and it can only pay the client.

∑

Overflow-safe

Checked arithmetic on every total, plus overflow checks compiled into the release build.

◎

Balance-verified funding

fund() checks the contract's real balance change, so a token with a transfer fee can't leave the escrow short.

⌀

No admin, no upgrade

No owner key, no sweep and no upgrade path. Funds only ever reach the client or the freelancer.
